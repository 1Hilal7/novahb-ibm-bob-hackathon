# novaHB — Blast Radius Analyzer

> **"Route attention, not notifications. Silence is a feature."**

novaHB is a hackathon MVP that answers the most important question after a commit:

**"Who actually needs to do something because of this change?"**

Not *"who is technically nearby?"* — but *"who genuinely needs to act?"*

---

## The Problem

Traditional blast-radius tools tell you:
- Which files changed
- Which modules depend on those files

novaHB goes further:

```
technically related != actually requires action
```

A developer who owns a module that depends on the changed code **does not automatically get an ACTION** notification if their code already handles the change safely.

---

## Demo Scenario

**The change:** `User.email` goes from required (`str`) to optional (`str | None`).

**The result:**

| Developer | Decision | Why |
|-----------|----------|-----|
| Batuhan | **ACTION** | `billing/invoice.py` uses `user.email.strip()` with no null guard — runtime error guaranteed |
| Emre | **REVIEW_REQUIRED** | Schema migration expert, currently working on `shared/user.py` |
| Ayşe | **SILENT** | `notifications/email.py` already guards `if user.email is None` |
| Hilal | **SILENT** | Auth task doesn't require non-null email |
| Selin | **SILENT** | No security invariant broken in this change |
| Mert | **SILENT** | Platform/infra has no user model dependency |

**6 developers → 1 ACTION, 1 REVIEW_REQUIRED, 4 SILENT**

## Architecture

```
Real Git Commit
  → Git Diff Extraction (git_analyzer.py)
  → Semantic Change Detection (semantic_detector.py)
  → Dependency Resolution (dependency_analyzer.py)
  → Source Safety Analysis via Python AST (relevance_analyzer.py)
  → Developer Task Overlap + Expertise Matching (router.py)
  → Impact Report Assembly (report_builder.py)
  → ImpactReport JSON (data/impact_report.json)
```

The routing engine uses a **deterministic rule engine**, not ML:

```
IF module is AFFECTED
AND developer's current_task_files overlap with that module
THEN ACTION

IF criticality == HIGH
AND developer is the schema/migration owner
AND their active task involves the changed file
THEN REVIEW_REQUIRED

IF dependent module is already safe (null guard detected by AST)
THEN SILENT

IF no dependency / task / expertise relevance
THEN SILENT
```

## API Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/health` | Liveness probe |
| `GET` | `/project` | Project module dependency map |
| `GET` | `/developers` | All 6 developer profiles |
| `POST` | `/analyze` | Run full analysis pipeline on HEAD |
| `GET` | `/impact/latest` | Latest generated impact report |
| `POST` | `/review/{developer_id}` | Expert approve/request_changes |

## Running

```bash
# Install dependencies
pip install -r backend/requirements.txt

# Start the server (from repo root)
uvicorn backend.app.main:app --reload --host 0.0.0.0 --port 8000

# Run all tests
python -m pytest tests/ -v

# Trigger analysis
curl -X POST http://localhost:8000/analyze

# Submit expert review
curl -X POST http://localhost:8000/review/emre \
  -H "Content-Type: application/json" \
  -d '{"decision": "approve"}'
```
